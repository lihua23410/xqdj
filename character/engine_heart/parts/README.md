# 泵之心零件包

每种零件是一个独立 Go 子包，行为在 `part.go`，外观在同目录 `fx.js`，特有样式可加 `fx.css`。不修改 `internal/unit`、`internal/sim` 或通用前端。

`api.Definition` 是统一接口：稳定 ID、名称、目录键，以及对本次装配 `api.Build` 的纯函数贡献。主包从当前仍装着的集合重建 Build；掉件不需要逆向减数值。行为可通过 Flow、Steer、Guards 和 WinchSpeed 扩展，不在主包增加按零件类型分支。

额外攻击组件还提供 `Weapon func() unit.Actor`，每个主人每次安装得到一个独立演员。它接收 Sense、碰撞、撞墙、眩晕以及角色包自己的 `api.Pulse` 和 `api.Detached`。充能、云区域、命中去重等状态都封装在该零件子包；调度按目录顺序，保证同种子重放顺序稳定。掉件移除演员并发送 Detached，复捡重新创建。`Select` 先保留一个 Weapon 非空的组件，再从剩余目录无放回抽六个，最后打乱位置；不能把纯加伤或被动捕弹件冒充这一保底。

需要攻击演员的零件还提供 Register(*unit.Pack)，由角色初始化时统一调用；所有规格仍属于本角色包。撞角与电弧使用现有 RegisterAttackFan/SyncAttackFan，碰撞伤害由扇环自身的 ID 发出，命中后再把 FanHit 转交零件演员处理运动与效果。不得在本体 Collision 或 FanHit 回调直接发 Damage；传导等二段伤害由独立攻击演员结算。回归应包含实际演员来源的 audit.CheckCommand，单测直接收集 Damage 不能代替运行时审计。

新增零件：

1. 建立新子包，使用从未占用的 ID；ID 不因排序改变。
2. 导出 `Definition()`，在 `catalog.go` 导入并加入目录。
3. 提供 `fx.js`，登记 `window.pumpParts[ID]` 的 name、color、site、mount、replaces 和 svg。mount 声明固定的 x/y 与 rear/front 层；site 描述实际安装部位；replaces 列出被升级取代的裸机 `data-socket`。SVG 根节点为 `g[data-part="ID"]`，按本零件安装原点绘制。支架、压力管道和功能件必须接入同一台机器，不使用通用圆周插槽或按拾取顺序排位置。场下直接复用这个完整 SVG，无须编写图标 draw 函数。
4. 所有 fx.js/css 由角色包 embed，现有资源加载器自动发现。
5. 新一局才可能抽到新增种类；已经抽定的七件不会中途变化。

角色渲染器只按 mount 平移零件；同一零件的安装位置与拾取栈深度无关。rear 位于炉心后面，front 位于炉心前面；同层按稳定 ID 排序，换序拾取不会改变遮挡。装上零件后隐藏其 replaces 声明的旧构件，掉落后恢复；复捡仍回原位。主包没有按零件 ID 硬编码安装分支。

拾取入栈统一由角色包的 installPart 处理：Weapon 非空的武器组件插在栈底，其余零件压到栈顶；掉件仍只弹出栈顶。武器复捡仍插入栈底，多件武器按新拾取者更靠底排列。分类与开局保底使用同一份目录信息，不在主包硬编码四个武器 ID。

SVG 根节点的 transform 由角色管理，运动部件须嵌套在内部 g。黑铁共享 `url(#ph-metal)`，黄铜共享 `url(#ph-brass)`；粗直角管道分别使用横向 `ph-pipeH` 和纵向 `ph-pipeV` 高光，弯头使用 `ph-elbow`。`--ph-fire`、`--ph-stroke`、`--ph-crank`、`--ph-wheel`、`--ph-turbine` 等变量来自模拟时间，暂停时不会继续运转。场下 SVG 使用相同材质定义并独立命名 ID，以自身完整包围盒居中，按固定世界坐标显示，飞散时整体旋转。场景显示框与物理留边集中在角色包管理。

攻击 FX 在本子包 `fx.js` 注册 `window.pumpAttackFX[name]={duration,draw(canvasContext,fx,age)}`，同时用 arena.registerShot 登记事件。X/Y 是起点，VX/VY 是终点或区域中心；场景负责世界坐标、寿命、同帧去重和边界裁切。新增零件的攻击绘制不需要在主渲染器增加 ID 分支。

持续攻击可声明 `channel`，同一主人同通道只保留最新几何；duration=0 的事件清除此通道。激光预警、发射与中断共用 laser 通道，电弧蓄电与清空共用 arc-charge 通道，传导爆闪独立短暂显示。持续伤害由零件演员按 Sense 与暴露间隔结算，不能由客户端特效或 Sense 频率决定。激光锁角后随发射者平移，电弧则只能经真实 Collision 起手，二者的触发、站位、伤害时间与反制条件均不同。

`motion` 声明零件所属机段：crown、chest、drive、keel 或 frame。根节点内包一层相应的 `.ph-motion-crown` 等 g，使零件随其机段刚性平移，同时保持根节点的固定 mount。四个机段依次收缩，黄铜套筒与滑轨承接段间行程；frame 是固定承力架。不要在零件根节点增加缩放或独立的墙钟动画。预览页的“逐段检查搏动”可以停在各段收缩姿态。

固定接口与本次结构设计：

- 增压活塞：左肋主泵缸；平行泵缸和铁制导轨钳住原主管，两个直角支路并入主管两端。
- 分流歧管：右上肩压力桥；双层粗管取代细旁通管，回路接回顶部主管与右肩机壳。
- 惯性飞轮：右下传动轴；加大轮毂、轴承座和供油回路，取代原来的小传动盖。
- 配气凸轮：右肋正时脊；封闭双凸轮轴沿机壳加厚，取代原来的右肋旁通管。
- 燃油喷嘴：炉窗下方燃烧室；双联喷嘴与燃油块接到横向主回路，向炉窗内部喷燃。
- 护心夹板：背部承力护架；沿肩、肋、底梁包覆黑铁护架。实际拦截钢板依旧缓慢绕机旋转，不造成伤害。
- 双联阀组：炉膛上方双联进气；两个手轮、阀体和支管在原进气端分流。
- 偏流叶轮：左上肩增压进气；加厚涡壳嵌入左肩，直角出气管并入烟囱主管。
- 捕弹阀笼：左下腹压力腔；替换下腹封口为带黄铜肋的压力容器，上端接入横向主管。
- 换向喷口：底部双向排气；将尾部封帽替换成双路排气机座，与躯干底梁连为一体。
- 回收绞盘：右下肋回收机构；通过承力梁与压力支管接回下部主管，卷轴、棘轮、导缆器组成一套总成。
- 蓄压光棱镜：炉窗聚焦光路；分段光阑、锁紧环与两侧黄铜供压线包围原炉窗，保留中间观察区。远距预警、锁角持续灼烧。
- 破阵撞角：下胸承力撞架；双侧撞角与厚横梁直接压在下胸主管的支座上。
- 蒸汽泄压缸：背部双联压力缸；左右厚壁压力容器与上部粗黄铜总管连为一体。
- 接触电弧线圈：顶部蒸汽发电线圈；替换烟囱端帽为双绕组发电冠，接回烟囱主管。近身搏动储电、碰撞释放与麻痹传导。

角色 `fx/preview.html` 直接调用 render 和 renderPart 接口，对比裸机、每一种单件安装、完整散件与三套七件混装。页面会用真实 DOM 校验十五种零件在换序、掉落、复捡后仍在同一位置、旧构件的隐藏恢复，以及散件的结构完整性。无需向实战注入装备状态。
