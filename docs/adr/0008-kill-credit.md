# 击杀记功在「发起伤害那一刻」定下来

勇者要「击杀活随从 +1 经验」。引擎原来根本不说谁杀了谁：`applyHurtLocked` 扣完血、`removeLocked` 清干净就完了，击杀者拿不到任何通知。于是要么新增一条通知，要么让勇者去猜。

决定：**新增 `unit.Kill`**，单位被打死时发给「记功对象」，带 `VictimID / VictimKind / VictimRole / Mortal`，收不收由角色自己决定。

决定：**记功对象在发起伤害那一刻就定下来，跟着伤害报价一起存**（`dmgOffer.credit`），不是等确认时才回头去找发起者。原因是一条实测教训：**发起者往往发完伤害当拍就自毁**——剑弧、法师弹、地慧星弹都是「发 `Damage` 然后立刻 `Despawn`」这个形态；等目标下一拍确认时 `m.units[from]` 已经是 nil，击杀就记丢了。第一版就是这么写的，实战里勇者打了整局一次经验都没涨。

决定：**记功对象 = 发起者本人；发起者有 owner 时记给它的主人**（owner 链只走一层，和 `holdsNoFrameFreeze` 同一套口径）。这样勇者的法师弹打死史莱姆，经验记在勇者头上；环境致死（没有来源）不发。

## Considered Options

- 让受害者自己在确认时给凶手发消息——每个吃伤害的单位都得配合写这段，别的角色的活随从不会配合，「击杀任何活随从」就退化成「只认自己的史莱姆」。
- 勇者自己轮询快照猜击杀（上一拍还在、这一拍没了）——多来源、多目标、同拍多杀时不可靠。
- 只在发起者还活着时记功——剑弧/子弹这类最常见的击杀形态全部记丢，等于没做。
