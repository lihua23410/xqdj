# 挡视线是实体标签，线判定直接焊进索敌，不进感知过滤

引擎的感知（`emitLocked` 按「中心距 ≤ 视野，自家白名单除外」裁 `Nearby`）从来没有视线遮挡这回事；想要"墙后藏身"时，备选有两条。改感知过滤（世界规则）：墙后的单位从感知里彻底消失，血契建线、雷达、所有自扫 Nearby 的逻辑全部连带改变——被拒，感知管道保持零改动。做成可选的索敌变体（新开一个查视线的 `SeekLOS` 等角色换用）：也被拒——名册 20 只球全走 `Seek`，没有任何角色会主动换用新函数，机制会死在场上没有消费者。

最终形态：`VisionBlock` 做成挂在实体上的标签——单位（`Spec.VisionBlock` 出生带，`VisionBlock` 令牌运行时挂摘，谁都能给谁挂、无权限校验）和 `PlaceWall` 造的墙（`PlaceWall.VisionBlock`）声明标签；线判定直接放进 `Seek` / `SeekIf` 的候选循环（墙按胶囊、单位按圆、相切算挡、敌我不分），凡是索敌默认尊重掩体。影响面被标签的存在性天然圈定：没有带标签实体的场地，`Seek` 行为逐字节不变，不必为每个角色单独开关。只挡索敌这一层：墙后的单位仍进感知，物理、碰撞出伤、激光镰刀这类不索敌的路径照常隔墙进行。

场地预放墙明确不带标签（`FieldWall` 没有这个字段）：场地是中立的舞台，只挡身体，永远不挡索敌。硬墙的方端不进视线判定（`WallView` 只有端点和半径，视线一律按胶囊量，方角差视为近似）。

八边形场地的三段挡视线硬墙是这条界线的正解：场地控制器（BootKind 演员）开局用 `PlaceWall{Hard, VisionBlock}` 砌出——走的是造墙链，不是预放链。预放墙不带标签的口径不变；挡视线始终是"演员造的战术"，场地中立原则没有被打破。
