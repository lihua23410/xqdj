# 对战视频：无头浏览器逐帧回放，而不是录屏或重画

观战页的“样子”不是一层薄壳：角色与场地特效分散在 218 个包文件、7539 行 CSS 和 8792 行 JS 里，还有 GSAP 时间线、逐角色的 `registerShot` / `regShot` 钩子，以及按拍更新的 DOM。把它在 canvas 里重画一遍，等于再养一套会分叉的观战页；录屏又会把浏览器的实时抖动、标签页节流和窗口尺寸带进成片，用户明确否掉了这个方案。

决定：服务端在对局进行时按拍记下完整的观众快照（含 `effects`、`units`、`walls`、`looks`、`packs`、`intro`、`winner`），导出时在无头 Chrome 里打开同一份 `index.html`，用 `?export=` 把页面切到导出态：把 `#arena .stage-wrap` 搬进 1080×1920 的 9:16 画布，画布中央放 5:6（1080×1296）的画面，上下留黑边；顶部是双方名字与 VS，底部是两条血条。页面里的时钟换成逐帧推进的假时钟，`requestAnimationFrame`、`setTimeout`、CSS 动画和 GSAP 都跟着同一个时间走；每推进一拍，`Page.captureScreenshot` 取一张 PNG，直接管进 ffmpeg 编成 60fps 的 H.264。成片开头停在第一拍 1 秒，结尾停在最后一拍 2 秒并在中央淡入胜者。

代价：导出依赖本机的 Chrome 和 ffmpeg，导出耗时约等于成片时长加编码时间；假时钟是只对导出页生效的全局补丁，首帧、末帧和中段必须逐段肉眼验，不能只看“能播”。在这条管线跑通 10 秒真实对局之前，本决定保持 proposed。
