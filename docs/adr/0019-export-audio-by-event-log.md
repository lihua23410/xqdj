# 导出音轨：记播放意图，服务端混音

观战页的声音不是一条背景轨，而是角色包里的 mp3 在具体特效发生时被 `new Audio(...).play()` 触发；每个角色后续都会加自己的声音，触发点跟着特效走。录屏式的实时收音会把浏览器的播放延迟、采样率和静音状态一起带进成片，也没法在导出时重放。

决定：导出页在逐帧回放时替换 `HTMLMediaElement.play/pause`，按绝对帧号记下 `{src, frame, volume, loop, rate, preservesPitch, offset}` 与停止事件，不真正出声。成片渲染完后，服务端按事件表把每个声音用 ffmpeg 解成 48kHz 双声道 f32，按 `frame * 800` 的采样位置混进一条 WAV（`rate != 1` 且保音高时用 `atempo`），再和 H.264 视频流封装成 MP4。事件表只记播放意图，不记实时波形，所以同一场对局重导两次得到同一条音轨。

代价：导出页必须走过每一个会触发声音的 `render`，否则事件会漏；音频文件路径来自角色包，需要服务端能读到同一份 `unit.BallFS()`。换角色时不需要改混音器，只要新角色继续用 `Audio.play()` 发声。
