# 声音按模式与优先级仲裁，而不是一个抢占布尔

原来的抢占只是一个布尔：抢占音起播时比较一次，之后没有办法表达“不抢占但也不被打断”“强制清场”这类行为。角色包越来越多，受击音、碰撞音、角色自己的长音、短音会同时出现，需要一个统一的裁决器。

决定：每个声音带 `mode`（0 非抢占、1 抢占、2 禁止抢占、3 强制抢占）和 `priority`（uint8，0–255，0 最低，1 最高）。所有播放经过同一个仲裁器：mode 1 在自己的播放窗口内停掉/拦住更低优先级的 mode 0/1，更高的声音可以在窗口内截断它；mode 2 有效优先级固定为 0，双向免疫 mode 1，但会被 mode 3 停掉并在 mode 3 期间禁止起播；mode 3 有效优先级固定为 1，起播停掉所有正在播的声音并锁住窗口，只有后到的 mode 3 能接管。平级时 mode 1 对 mode 1 后到赢、对 mode 0 抢占赢，mode 0 之间共存。被停掉的声音不恢复。

代价：每个声音都必须走仲裁器，不能再直接 `new Audio(...).play()`；角色包要显式声明模式和优先级，未声明时按 mode 0 / priority 0。仲裁窗口依赖“仍在播放”这一事实，所以暂停、命中停顿和导出页的假时钟都要共用同一套 active 判断，否则正常对局与导出会听到不同的结果。
