# 片头按帧号算样式，不挂在假时钟上

导出页的动画本来都跟着一条假时钟走：`export-clock.js` 替换 `performance.now`、`requestAnimationFrame` 和 `setTimeout`，GSAP 时间线与 CSS 动画因此和逐帧推进同频，假时钟进多少、画面就走多少。片头不能吃这条时钟。它排在正片之前（一秒钟逐个点出双方名字与 VS、三秒移到顶栏、一秒画面元素浮现），而假时钟的 `setNow` 只进不退、比赛帧又固定从 0 重新对齐：片头一推进时钟，页面里残留的 `setTimeout`、角色 fx 的 GSAP 时间线、首拍的 CSS 动画都会跟着提前走，等正片开拍时已经错位——片头越像成品，开头几拍越对不上。

决定：片头单独一条纯时间轴。`applyIntro(帧号)` 是帧号的纯函数，由它算三行文字的 `translate` / `opacity` / `scale` 与画布上的 `--intro-hud`，直接写内联样式；不建 timeline、不调 `clock.set`，正片帧照旧走假时钟。同一帧号永远得到同一画面，同一场对局重导两次逐帧一致。

代价：片头的缓动要手写（三次缓入缓出等），用不了 GSAP 的现成曲线和时间线组合；片头的每个值都必须能从帧号推出来，`onComplete` 一类的回调在这里没有位置。片头与正片的进度是两套时钟，任何“从片头延续进正片”的动效都得自己在边界帧上手工接上。
