# 开场演出由资源包注册，公共层只负责调度

本决定替代 0025 中专门保存 `IntroFilm` 和计算 `ProbeFrames` 的协议。该实现虽然修复了非因果导出，但将死亡时间、倒带时长和轨迹绘制放进通用层，新增演出仍需修改导出核心。

决定：以 `replay.Presentation` 描述资源包、类型、时长、音频开关与不透明 JSON 数据，通过 `Match.QueueOpening` 提交。开场可以由多段组成，通用层只处理顺序、时间、记录和结束回执。

前端由各资源包调用 `arena.registerPresentation` 注册 mount/render/destroy。普通观战和导出使用同一调度器、相同数据及段内时间；调度器提供独立容器、资源回收和受控音频。静态预览不播放音频，开始实际播放时重新挂载。结束回执按当前队列最后一段 ID 验证，ID 在同一 Match 的多场比赛间不复用。

非因果的轨迹协议、时长计算、绘制和样式均迁回自己的包。现有探针模拟编排保持原位，本决定不扩展至局中演出或改变探针战斗规则。

测试通过独立文本数据的第二种播放器、同类型不同包的注册、普通观战适配、连续演出、音频开关、异常清理和真实 MP4 验证扩展边界。新演出不需要修改 app.js、export.js 或编码器。接入契约见 ../presentations.md。
