# 战斗机协作状态归属于本场，出生参数跟随出生请求

胜率工具会同时运行多场对局，各场重复使用单位编号；相同种子也会重复使用出生流号。进程级的主人表、挡伤标记、击杀奖励和出生参数队列即使加锁，仍会让一场读到另一场的数据，或在重置时清掉另一场的记录。

决定：Match 每次开局创建独立的 `unit.MatchState`，通过 `SpawnInfo.State` 和 `Context.State` 传给本场演员。各包用自己的私有状态类型取得本场共享值，内部锁仍由各包维护；重开和结束先等旧演员退出，再更换作用域。非因果探针是独立的 Match，使用自己的作用域。静态配置和注册表仍可在初始化后只读共享。

只在出生时使用的鱼重、票面、撕咬伤害、图形参数、小炮击延迟、人偶规格和钉子仪式参数，改放 `Spawn.Data`，由引擎原样传给该次出生的 `SpawnInfo.Data`。不再借全局队列或流号表转交；数据类型与解释留在私产包，引擎不按战斗机名字分支。引用数据必须不可变或转移所有权，不进快照。

不采用全局唯一单位编号作为修补：按边保存的计数、清空整张表和无键队列仍会串场。也不把每只战斗机的状态字段写进 Match，避免引擎依赖私产结构。分身者(百战)重整只清自己的战影挡伤，不能清同场另一只的挡伤。

本条补齐 ADR 0024 未覆盖的战斗机可变私产隔离。演员异步处理、事件队列溢出以及停帧与胜率超时的口径仍需分别处理；本次隔离不等于固定种子已能确定性重放。
