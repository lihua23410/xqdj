# 角色事件可靠投递，阶段交接施加背压

旧收件箱容量 64，满时静默丢弃所有事件。慢角色的旧感知会挤掉 IncomingDamage，而伤害必须由角色确认才扣血，导致吞吐与调度负载决定伤害是否生效。300 场“小骑士 vs 雷达”串行诊断中，发往雷达的 6,046 次伤害通知有 4,184 次丢失，已处理感知平均落后约 183 拍。增加缓冲或多调用 Gosched 无法保证规则可靠执行。

决定：每个角色使用可扩容的 FIFO 收件箱，保留每拍 Sense 和规则事件，不做感知合并。只有单位离场、停场时才取消尚未处理的队列项；正在执行的 Handle 仍要结束，停场继续排空它的输出并等待协程退出。队列项和执行中的 Handle 共同计入本场未完成工作。

引擎沿用已有的命令结算边界，每个边界先接收当前已投递事件产生的命令，直到这些 Handle 全部结束，再按命令到达顺序应用这一批命令。等待期间必须持续接收命令，避免角色卡在满命令通道、引擎又等角色完成的死锁。应用命令新产生的事件由下一个边界承接，不在同一边界无限追踪反应链。背压同时覆盖 Play、正常 Tick、非因果探针和实时 Loop。

所有角色仍在独立协程里执行，没有按单位编号顺序调用 Handle，也没有规定不同角色命令的到达顺序。相同种子仍允许局面或胜负差异。ADR 0030 保留的是这种异步先后差异，不包括因机器负载而丢伤害或持续落后多拍。

不采用临时感知限流实验作为修复：丢弃或合并中间感知会改变索敌、激光和出招的采样频率。也不靠任意扩大缓冲区来容忍积压；队列解决可靠投递，阶段背压限制跨拍落后。过载时让模拟推进变慢，代价是吞吐量取决于实际完整规则的计算成本。

验证包括：超过旧容量的伤害投递、逐拍 FIFO、关闭时排队与执行中事件的计数、慢角色背压、1,024 条命令不死锁、反应延至下一个边界、角色仍可并发执行、停场退出，以及串行/并行配对复测。旧矩阵应保留为缺陷诊断数据，修复后重新生成。

修复后的定向复测覆盖先前筛出的 16 组对阵、每组每种并发各 200 场（同一批第 101–300 号种子）。前者胜率最大串并行差由 84 个百分点降至 5 个百分点，48 个终点经配对检验与 Holm 校正后未检出显著差异；3,200 个同种子输入仍有 71 局胜负不同。另做 1,431 组各 2 场的全矩阵集成检查，以及全部 Go 测试和模拟包完整 race 检查。这个范围用于复核已发现的缺陷，不等于证明所有对阵在任意并发下概率完全相同，也未重新生成每组 100 场的全量矩阵。
