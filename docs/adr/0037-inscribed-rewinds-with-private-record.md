# 铭刻用私有记录槽还原，不扩引擎协议

时计·铭刻 需要保存并在之后还原一整套自身状态（手牌、抽卡进度、血量与上限、两种 buff 层数、速度、位置、20 秒冷却剩余）。引擎没有通用快照 API，快照结构体里也读不到巡航基础值、固定加伤、眩晕剩余。

决定：**记录槽就是这只角色自己的一个结构体，还原时按固定顺序把现有指令逐条发出去**——`Teleport` → `SetHP`（HP 与 MaxHP 同时写，因为只降上限不夹当前血）→ `SetCruise` → `SetVelocity` → `SetFSDirection` → `Stun{false}` → `ClearMarks` → 逐条 `StackMark` 回放 → `SetDamageBonus`。卡牌、抽卡进度这类私产本来就在 actor 里，不进协议。致命伤不做拦截（这套牌没有自动保命），所以也不需要 `BlockHit`。

不扩协议的理由：时计已经证明这条路走得通（`CONTEXT.md` 的「时计」条目、`docs/adr` 同期的做法），而新增一条「快照/还原」指令等于把每个角色的私有状态都塞进引擎；引擎并不知道什么叫「卡牌」「抽卡进度」。

已知代价，都写进角色注释里：marks 只能还原层数、还原不了每层剩余寿命（这两个 buff 是永久的，不受影响）；`SetVelocity` 写进去会被当前的减速倍率再乘一次，且会向巡航值衰减，所以回溯是「回到那一刻的速度」，不是锁死。
